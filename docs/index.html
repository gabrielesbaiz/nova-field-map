    A map field that behaves like a Nova field.

    01  /  The smallest real thing

    Two arguments. That is the whole field.

    No type(), no handing the data in yourself. Name the field, name the column, and the resolver chain works out what it found.

    app/Nova/Warehouse.php
    use Gabrielesbaiz\NovaFieldMap\FieldMap;

public function fields(NovaRequest $request): array
{
    return [
        FieldMap::make('Location', 'coordinates'),
    ];
}

    02  /  Editable

    Two more calls and an administrator places the pin.

    2.x forced showOnUpdate to false and shipped a text input that did nothing. 3.0 gives you a real form field: click to place, drag to adjust, search for a place, or type the numbers.

    03  /  A whole relation

    One marker per related record, clustered, clickable.

    Each related record's attributes travel with its feature, so popups and per-marker styling address them by column name. linkToResource() makes a marker click open that record's detail page through Inertia.

    A store locator
    public static $with = ['branches'];

FieldMap::make('Branches', 'coordinates')
    ->relation('branches')
    ->popup('name')
    ->linkToResource()
    ->cluster(disableAtZoom: 12)

// popup('name') is escaped. Markup needs
// an explicit ->allowHtmlPopups().

    05  /  What changed in 3.0

    A rewrite, driven by three things that were wrong.

    01

    Popups were an XSS hole

    Leaflet's bindPopup() renders a string as HTML, and 2.x passed feature properties to it untouched. Anyone who could write that column could run JavaScript in an administrator's session. Content is now escaped in PHP; markup needs an explicit opt-in and is still sanitised in the browser.

    02

    It leaked on every navigation

    The map was never removed on unmount, so each Inertia page change left a live Leaflet instance and its handlers on detached DOM. 3.0 calls map.remove() and disconnects both observers — and a test asserts it.

    03

    Every page paid for Leaflet

    2.x shipped one 74.3 kB gzipped bundle on every Nova page, map or no map. The entry bundle is now 11.2 kB; Leaflet arrives only when a map is about to become visible.

    06  /  When not to use this

    If two number fields will do, use two number fields.

    Showing a latitude and a longitude is not a reason to load a mapping library. Two Number fields are less JavaScript, less to go wrong, and an administrator who knows the coordinates can simply type them.

    Use Nova's own fields when…

    Number::make('Latitude')->step(0.000001),
Number::make('Longitude')->step(0.000001),
    • The coordinates are data, not a place anyone needs to see.
    • Nobody is verifying the location by looking at it.
    • Your index tables need a location column and nothing more.

    Use FieldMap when…

    FieldMap::make('Location', 'coordinates')
    ->editable()
    ->geocoder(),
    • Somebody has to confirm the warehouse is on the right side of the motorway.
    • Fifty branches need to be seen at once, and the gap noticed.
    • The person knows where the site is, but not its coordinates.
    • A delivery-zone polygon has to be checked against the estate.
